# SD-VLM: Spatial Measuring and Understanding with Depth-Encoded Vision-Language Models

**Citation**: Pingyi Chen, Yujing Lou, Shen Cao, Jinhui Guo, Lubin Fan, Yue Wu, Lin Yang, Lizhuang Ma, Jieping Ye. NeurIPS 2025. arXiv:2509.17664. https://arxiv.org/abs/2509.17664 (HTML read: https://arxiv.org/html/2509.17664v1)
**Read on**: 2026-10-24 (abstract, method section 4, experiments section 5–6, appendices A, C and D via the HTML version)

## TL;DR
The paper adds a parameter-free sinusoidal encoding of per-patch depth to the CLIP image features of LLaVA-1.5-7B and fine-tunes with LoRA on a 700K-QA metric-spatial dataset built from ScanNet/ScanNet++ (MSMU). Depth as an additive positional encoding beats every other way of feeding depth: giving the depth map as a second image is far worse than giving no depth at all.

## Setup / method
- **Input**: one RGB image, the depth map for that image (ground truth from ScanNet scans, or Depth-Anything-V2 when GT is unavailable), and a text question. No camera intrinsics are used. Appendix A argues they are recoverable in principle, but this is not tested.
- **Depth positional encoding (DPE)**: the depth map is adaptively mean-pooled onto the CLIP feature grid (one scalar per patch). It is then min-max normalised and scaled by α (best α = 100; 50 → 49.50, 200 → 53.67, 500 → 52.98 on MSMU-Bench). Next it is passed through the standard transformer sin/cos formula (frequencies 10000^(2t/d)) and added element-wise to the image features: "integrating depth positional embeddings into image embeddings by adding". This is scalar depth, not xyz. The paper does not say whether min/max are per image or per dataset, so absolute metric scale may not be preserved in the encoding.
- **Model / training**: LLaVA-1.5-7B with a frozen CLIP-ViT/14. LoRA on the LLM (lr 2e-4), projector trained (lr 2e-5). One epoch on MSMU, about 32 V100-GPU-hours.
- **Supervision**: templated QA with numeric answers (sizes, distances, counts, 2D grounding, relative position), plus a 10K chain-of-thought subset generated by Qwen2.5-VL and filtered by DeepSeek-V3. Scoring: success if max(d̂/d*, d*/d̂) ≤ 1.25, with GPT-4 used to extract numbers.

## Key results
- MSMU-Bench average success: SD-VLM 56.31 (59.19 with CoT) vs GPT-4o 32.28, Gemini-2 35.17, InternVL3-78B 33.63, Qwen2.5-VL-72B 30.82, SpatialRGPT 28.98, SpatialBot 29.17, LLaVA-1.5-7B 19.45. The abstract's "+26.91% over GPT-4o" is the CoT variant.
- Per task: existence 87.23, relative position 75.16, absolute distance 40.00, 2D grounding 42.53. Metric tasks remain the weakest.
- Transfer: Q-Spatial++ 56.2 (InternVL3-78B 53.6, GPT-4o 52.0), and SpatialRGPT-Bench quantitative 33.3 (SpatialRGPT 28.7). The benchmark was re-annotated, so it is not the official protocol.
- **Depth-injection ablation (MSMU-Bench, Table 2 right)**: no depth 46.73, **depth as image 22.64**, depth as prompt (text values from an API) 48.78 (the text says 47.78), depth as token (concatenated) 35.72, DPE with estimated depth 55.35, DPE-learnable 56.18, DPE-sincos 56.31.
- **GT vs estimated depth (Appendix C)**: train GT / test GT 57.71, GT / estimated 56.31, estimated / GT 54.17, estimated / estimated 55.35, none 46.73. Depth-Anything-V2 and UniDepth give almost the same results (56.3 vs 56.2).
- **Noise robustness**: Gaussian noise σ = 0.1/0.3/0.5/0.7 on the normalised depth gives 55.1/54.0/53.3/51.4. All of these stay above no-depth (46.7).

## Relevance to us
- **IDEA-005 (depth as a second image)**: this is the most direct evidence against it. In their setting, depth as an extra image more than halved performance relative to no depth (22.64 vs 46.73). Concatenating depth tokens also hurt (35.72). Only additive injection into the existing visual tokens helped. We should not spend a GPU run on IDEA-005 before an additive variant.
- **IDEA-013 (per-patch xyz PE)**: the paper validates the core mechanism, additive per-patch geometry on visual tokens with only LoRA adaptation, in a single-image setting like ours. It also offers a cheaper lower rung: scalar depth, sinusoidal, no MLP (IDEA-020). The learnable and fixed encodings were equal (56.18 vs 56.31), so the MLP in IDEA-013 may not be necessary.
- **val_ood_config (camera elevation 12–25°)**: a per-patch depth signal gives the model metric distance along each ray directly, so camera-frame z no longer has to be inferred from a viewpoint-specific appearance→depth map. That is the hypothesised mechanism of our config Task A failure (0.016 → 0.136 m). If depth PE closes most of the gap, that supports the camera-elevation hypothesis over object count/clutter. If it does not, count/omission or clustering is implicated (pair with IDEA-006/007).
- **The RGB-only claim**: the estimated-depth rows (55.35 when trained and tested on estimated depth, vs 57.71 GT/GT) suggest that a Depth-Anything follow-up to IDEA-013 would keep most of the gain. Our sim images are synthetic, though, and the estimator's domain gap is untested here.
- **Task B / force conditioning**: not addressed. The paper is static-scene only.

## Ideas for us
- **IDEA-020 Scalar metric-depth sinusoidal PE (cheap rung below IDEA-013)**: mean-pool `depth_t0` onto Qwen3-VL's merged-token grid. Encode depth in metres with a fixed scale (not per-image min-max, since our targets are metric) via sin/cos. Add it to the visual tokens after the merger through one zero-initialised scalar gate, and train only the gate plus the existing LoRA. The image ablations drop or swap the PE too. Expected: most of IDEA-013's Task A gain on val_ood_config at a fraction of the surgery. If scalar depth is enough, the xyz/MLP machinery is unnecessary. Cost: about 0.5–1 day of code plus about 1.5 GPU h.
- No separate idea for "depth as prompt" (text depth values): for us, the per-object depth would leak the Task A z target almost directly.
- I added a note to IDEA-005 (depth as a second image): deprioritise it, given the 22.64 vs 46.73 result.

## Caveats / disagreements
- The base model is LLaVA-1.5 with frozen CLIP, not Qwen3-VL with a native-resolution ViT and patch merger. Qwen3-VL's features may react differently to added sinusoids.
- The metric is a coarse ratio threshold (δ ≤ 1.25), so a 25% error counts as a success. Our metric is Euclidean metres, where a 25% depth error at ~1 m is a failure.
- Min-max normalisation (scope unspecified) may discard absolute scale. Their gains could come from relative-depth ordering more than metric depth. We need absolute depth.
- Indoor real scans with varied viewpoints. There is no controlled viewpoint-shift test, so the paper does not show that DPE fixes an elevation OOD split specifically.
- Text/table inconsistencies (47.78 vs 48.78, and 56.18 vs 56.31 as "the" DPE number). The source of depth for the headline 56.31 is ambiguous; Appendix C implies a GT-trained / estimated-tested setting.
- The scoring relies on GPT-4 to extract numbers.
